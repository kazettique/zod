若要驗證資料，必須先定義一個*架構（schema）*。架構代表*型別*，型別可以是簡單的基礎值亦或複雜的巢狀物件和陣列。

## 基礎型別

```ts
import * as z from "zod";

// primitive types
z.string();
z.number();
z.bigint();
z.boolean();
z.symbol();
z.undefined();
z.null();
```


### 強制轉型

若要對輸入資料強制轉型，請改用 `z.coerce`：

```ts
z.coerce.string();    // String(input)
z.coerce.number();    // Number(input)
z.coerce.boolean();   // Boolean(input)
z.coerce.bigint();    // BigInt(input)
```

這些帶有強制轉型的架構會嘗試將輸入值轉型為目標型別。

```ts
const schema = z.coerce.string();

schema.parse("tuna");    // => "tuna"
schema.parse(42);        // => "42"
schema.parse(true);      // => "true"
schema.parse(null);      // => "null"
```

這些強制架構的對輸入值的預設型別為 `unknown`。若要指定更特定的輸入值型別，請傳入一個泛用型別參數：

```ts
const A = z.coerce.number();
type AInput = z.input<typeof A>; // => unknown

const B = z.coerce.number<number>();
type BInput = z.input<typeof B>; // => number
```

<Accordions type="single">
<Accordion title="Zod 中的強制轉型如何運作">
  
  Zod 使用內建的建構式來轉換輸入值。

  | Zod API                  | 強制轉型                    |
  |--------------------------|----------------------------|
  | `z.coerce.string()`      | `String(value)`            |
  | `z.coerce.number()`      | `Number(value)`            |
  | `z.coerce.boolean()`     | `Boolean(value)`           |
  | `z.coerce.bigint()`      | `BigInt(value)`            |
  | `z.coerce.date()`        | `new Date(value)`          |

  使用 `z.coerce.boolean()` 進行的布林型別轉換可能與預期不同。任何 [truthy](https://developer.mozilla.org/en-US/docs/Glossary/Truthy) 值會被強制為 `true`，而任何 [falsy](https://developer.mozilla.org/en-US/docs/Glossary/Falsy) 值會被強制為 `false`。

  ```ts
  const schema = z.coerce.boolean(); // Boolean(input)

  schema.parse("tuna"); // => true
  schema.parse("true"); // => true
  schema.parse("false"); // => true
  schema.parse(1); // => true
  schema.parse([]); // => true

  schema.parse(0); // => false
  schema.parse(""); // => false
  schema.parse(undefined); // => false
  schema.parse(null); // => false
  ```

  若要完全控制強制轉型的邏輯，請考慮使用 [`z.transform()`](#transforms) 或 [`z.pipe()`](#pipes)。

</Accordion>
<Accordion title="自訂輸入值型別">
  
  預設情況下，任何 `z.coerce` 架構的_輸入_型別是 `unknown`。在、某些情況下，輸入值的型別可能比較特殊。您可以使用泛用型別參數指定輸入值的型別。

  ```ts
  const regularCoerce = z.coerce.string();
  type RegularInput = z.input<typeof regularCoerce>; // => unknown
  type RegularOutput = z.output<typeof regularCoerce>; // => string

  const customInput = z.coerce.string<string>();
  type CustomInput = z.input<typeof customInput>; // => string
  type CustomOutput = z.output<typeof customInput>; // => string
  ```

</Accordion>
</Accordions>



## 實字（Literals）

實字架構代表一個 [實字型別（literal type）](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#literal-types)，例如：`"hello world"` 或 `5`。

```ts
const tuna = z.literal("tuna");
const twelve = z.literal(12);
const twobig = z.literal(2n);
const tru = z.literal(true);
```

欲表示 JavaScript `null` 和 `undefined` 的實字型別：

```ts
z.null();
z.undefined();
z.void(); // equivalent to z.undefined()
```

允許複數的實字值：

```ts
const colors = z.literal(["red", "green", "blue"]);

colors.parse("green"); // ✅
colors.parse("yellow"); // ❌
```

從實字架構中抽取出允許值的集合（Set）：

```ts
colors.values; // => Set<"red" | "green" | "blue">
```
</Tab>

```ts
// no equivalent
```

### 電子郵件

欲驗證電子郵件地址：

```ts
z.email();
```

預設情況下，Zod 使用相對嚴格的電子郵件正規表達式來驗證包含一般字元的一般電子郵件地址。它與 Gmail 強制執行的規則大致相同。要瞭解有關這個 regex 的更多資訊，請參閱[這篇文章](https://colinhacks.com/essays/reasonable-email-regex)。

```ts
/^(?!\.)(?!.*\.\.)([a-z0-9_'+\-\.]*)[a-z0-9_+-]@([a-z0-9][a-z0-9\-]*\.)+[a-z]{2,}$/i
```

若要自訂電子郵件驗證行為，可以傳送自訂的正則表達式到 `pattern` 參數。

```ts
z.email({ pattern: /your regex here/ });
```

Zod 輸出幾個常用的正規表達式。

```ts
// Zod's default email regex
z.email();
z.email({ pattern: z.regexes.email }); // equivalent

// the regex used by browsers to validate input[type=email] fields
// https://developer.mozilla.org/en-US/docs/Web/HTML/Element/input/email
z.email({ pattern: z.regexes.html5Email });

// the classic emailregex.com regex (RFC 5322)
z.email({ pattern: z.regexes.rfc5322Email });

// a loose regex that allows Unicode (good for intl emails)
z.email({ pattern: z.regexes.unicodeEmail });
```

### UUIDs

欲驗證 UUIDs：

```ts
z.uuid();
```

欲指定特定的 UUID 版本：

```ts
// supports "v1", "v2", "v3", "v4", "v5", "v6", "v7", "v8"
z.uuid({ version: "v4" });

// for convenience
z.uuidv4();
z.uuidv6();
z.uuidv7();
```

RFC 9562/4122 UUID 規格要求位 8 元組的前兩個位元為 `10`。其他類 UUID 的識別碼不強制執行此限制。欲驗證任何類似 UUID 的識別碼：

```ts
z.guid();
```

### URLs

欲驗證任何與 WHATWG 相容的 URL：

```ts
const schema = z.url();

schema.parse("https://example.com"); // ✅
schema.parse("http://localhost"); // ✅
schema.parse("mailto:noreply@zod.dev"); // ✅
```

如您所見這相當寬鬆。其內部使用 `new URL()` 建構式來驗證輸入值；其行為在不同的平台和執行環境很可能會有所不同，但在任何特定的 JS 執行環境/引擎上，這已是驗證 URIs/URLs 最嚴格的方式。

根據特定的正規表達式驗證主機名稱：

```ts
const schema = z.url({ hostname: /^example\.com$/ });

schema.parse("https://example.com"); // ✅
schema.parse("https://zombo.com"); // ❌
```

若要根據特定 regex 驗證通訊協定，請使用 `protocol` 參數。

```ts
const schema = z.url({ protocol: /^https$/ });

schema.parse("https://example.com"); // ✅
schema.parse("http://example.com"); // ❌
```

<Callout>
  **Web URL** - 在許多情況下需要特別驗證 Web URL。建議如下：

  ```ts
  const httpUrl = z.url({
    protocol: /^https?$/,
    hostname: z.regexes.domain
  });
  ```

  這會限制通訊協定為 `http`/`https`，並確保主機名稱是使用 `z.regexes.domain` 正則表達式的有效網域名稱：

  ```ts
  /^([a-zA-Z0-9](?:[a-zA-Z0-9-]{0,61}[a-zA-Z0-9])?\.)+[a-zA-Z]{2,}$/
  ```
</Callout>

欲將 URL 正規化，請使用 `normalize` 標誌。這會用 `new URL()` 回傳的 [正規化 URL](https://chatgpt.com/share/6881547f-bebc-800f-9093-f5981e277c2c)覆蓋其輸入值。

```ts
new URL("HTTP://ExAmPle.com:80/./a/../b?X=1#f oo").href
// => "http://example.com/b?X=1#f%20oo"
```

### ISO 日期時間

您可能會注意到 Zod 字竄包含一些日期/時間相關的驗證。這些驗證基於正則表達式實作而成，因此不像專門的日期/時間函式庫驗證那麼嚴格。不過，它們對於驗證使用者的輸入值非常方便。

`z.iso.datetime()` 方法強制執行 ISO 8601；預設不允許設定時區：

```ts
const datetime = z.iso.datetime();

datetime.parse("2020-01-01T06:15:00Z"); // ✅
datetime.parse("2020-01-01T06:15:00.123Z"); // ✅
datetime.parse("2020-01-01T06:15:00.123456Z"); // ✅ (arbitrary precision)
datetime.parse("2020-01-01T06:15:00+02:00"); // ❌ (offsets not allowed)
datetime.parse("2020-01-01T06:15:00"); // ❌ (local not allowed)
```

欲設定時區：

```ts
const datetime = z.iso.datetime({ offset: true });

// allows timezone offsets
datetime.parse("2020-01-01T06:15:00+02:00"); // ✅

// basic offsets not allowed
datetime.parse("2020-01-01T06:15:00+02");    // ❌
datetime.parse("2020-01-01T06:15:00+0200");  // ❌

// Z is still supported
datetime.parse("2020-01-01T06:15:00Z"); // ✅ 
```

設定無限定（無時區）日期時間：

```ts
const schema = z.iso.datetime({ local: true });
schema.parse("2020-01-01T06:15:01"); // ✅
schema.parse("2020-01-01T06:15"); // ✅ seconds optional
```

欲限制時間精度（`precision`），預設情況下，秒是選填的，並允許設定秒以下的精度。

```ts
const a = z.iso.datetime();
a.parse("2020-01-01T06:15Z"); // ✅
a.parse("2020-01-01T06:15:00Z"); // ✅
a.parse("2020-01-01T06:15:00.123Z"); // ✅

const b = z.iso.datetime({ precision: -1 }); // minute precision (no seconds)
b.parse("2020-01-01T06:15Z"); // ✅
b.parse("2020-01-01T06:15:00Z"); // ❌
b.parse("2020-01-01T06:15:00.123Z"); // ❌

const c = z.iso.datetime({ precision: 0 }); // second precision only
c.parse("2020-01-01T06:15Z"); // ❌
c.parse("2020-01-01T06:15:00Z"); // ✅
c.parse("2020-01-01T06:15:00.123Z"); // ❌

const d = z.iso.datetime({ precision: 3 }); // millisecond precision only
d.parse("2020-01-01T06:15Z"); // ❌
d.parse("2020-01-01T06:15:00Z"); // ❌
d.parse("2020-01-01T06:15:00.123Z"); // ✅
```

### ISO 日期

`z.iso.date()` 方法驗證字串的格式為 `YYYY-MM-DD`。

```ts
const date = z.iso.date();

date.parse("2020-01-01"); // ✅
date.parse("2020-1-1"); // ❌
date.parse("2020-01-32"); // ❌
```

### ISO 時間

`z.iso.time()` 方法驗證字串的格式為 `HH:MM[:SS[.s+]]`。預設秒是選填的，秒的小數點也是選填的。

```ts
const time = z.iso.time();

time.parse("03:15"); // ✅
time.parse("03:15:00"); // ✅
time.parse("03:15:00.9999999"); // ✅ (arbitrary precision)
```

不允許任何形式的時區偏移。

```ts
time.parse("03:15:00Z"); // ❌ (no `Z` allowed)
time.parse("03:15:00+02:00"); // ❌ (no offsets allowed)
```

使用精度參數（`precision`）來限制允許的小數精度。

```ts
z.iso.time({ precision: -1 }); // HH:MM (minute precision)
z.iso.time({ precision: 0 });  // HH:MM:SS (second precision)
z.iso.time({ precision: 1 });  // HH:MM:SS.s (decisecond precision)
z.iso.time({ precision: 2 });  // HH:MM:SS.ss (centisecond precision)
z.iso.time({ precision: 3 });  // HH:MM:SS.sss (millisecond precision)
```

### IP 區塊（CIDR）

驗證以[CIDR 表示法（無類別域間路由）](https://en.wikipedia.org/wiki/Classless_Inter-Domain_Routing)所指定的 IP 位址範圍。

```ts
const cidrv4 = z.cidrv4();
cidrv4.parse("192.168.0.0/24"); // ✅

const cidrv6 = z.cidrv6();
cidrv6.parse("2001:db8::/32"); // ✅
```

### MAC 位址

驗證標準 48 位元 MAC 位址 [IEEE 802](https://en.wikipedia.org/wiki/MAC_address)。

```ts
const mac = z.mac(); 
mac.parse("00:1A:2B:3C:4D:5E");  // ✅
mac.parse("00-1a-2b-3c-4d-5e");  // ❌ colon-delimited by default
mac.parse("001A:2B3C:4D5E");     // ❌ standard formats only
mac.parse("00:1A:2b:3C:4d:5E");  // ❌ no mixed case

// custom delimiter
const dashMac = z.mac({ delimiter: "-" });
dashMac.parse("00-1A-2B-3C-4D-5E"); // ✅
```

### 雜湊表

驗證加密的雜湊值：

```ts
z.hash("md5");
z.hash("sha1");
z.hash("sha256");
z.hash("sha384");
```

```ts
z.hash("sha256", { enc: "hex" });       // default
```

### 自訂格式

欲自定義字串格式：

```ts
const coolId = z.stringFormat("cool-id", ()=>{
  // arbitrary validation here
  return val.length === 100 && val.startsWith("cool-");
});

// a regex is also accepted
z.stringFormat("cool-id", /^cool-[a-z0-9]{95}$/);
```

此架構會產生 `"invalid_format"` 錯誤訊息，比起經由精煉（refinements）或 `z.custom()` 產生的 `"custom"` 錯誤更能說明錯誤的內容。

```ts
myFormat.parse("invalid input!");
// ZodError: [
//   {
//     "code": "invalid_format",
//     "format": "cool-id",
//     "path": [],
//     "message": "Invalid cool-id"
//   }
// ]
```

## 樣板實字（Template literals）

> **新功能** - 自 `zod@4.0` 版本推出。

欲定義樣板實字架構：

```ts
const schema = z.templateLiteral([ "hello, ", z.string(), "!" ]);
// `hello, ${string}!`
```

`z.templateLiteral` API 可以處理任意數量的字串實字（例如：`"hello"`）和架構，任何具備可賦值為 `string | number | bigint | boolean | null | undefined` 推論型別的架構都可以使用。

```ts
z.templateLiteral([ "hi there" ]);
// `hi there`

z.templateLiteral([ "email: ", z.string() ]);
// `email: ${string}`

z.templateLiteral([ "high", z.literal(5) ]);
// `high5`

z.templateLiteral([ z.nullable(z.literal("grassy")) ]);
// `grassy` | `null`

z.templateLiteral([ z.number(), z.enum(["px", "em", "rem"]) ]);
// `${number}px` | `${number}em` | `${number}rem`
```

## 字串布林值 [#字串布林值]

> **💎 Zod 4 的新功能**

某些情況下（例如：解析環境變數）將某些字串的「類布林值」（boolish）解析成「純布林值」是很有用的。為了實現這一點，Zod 4 引入了 `z.stringbool()` 方法：

```ts
const strbool = z.stringbool();

strbool.parse("true")         // => true
strbool.parse("1")            // => true
strbool.parse("yes")          // => true
strbool.parse("on")           // => true
strbool.parse("y")            // => true
strbool.parse("enabled")      // => true

strbool.parse("false");       // => false
strbool.parse("0");           // => false
strbool.parse("no");          // => false
strbool.parse("off");         // => false
strbool.parse("n");           // => false
strbool.parse("disabled");    // => false

strbool.parse(/* anything else */); // ZodError<[{ code: "invalid_value" }]>
```

欲自訂真值（truthy）和偽值（falsy）：

```ts
// these are the defaults
z.stringbool({
  truthy: ["true", "1", "yes", "on", "y", "enabled"],
  falsy: ["false", "0", "no", "off", "n", "disabled"],
});
```

預設架構是*不區分大小寫*（case-insensitive）的；所有輸入值在與真/偽值比較之前皆會轉換為小寫。若要使它對區分大小寫，請加入以下設定：

```ts
z.stringbool({
  case: "sensitive"
});
```

### 安全擴充（`.safeExtend()` 方法）

`.safeExtend()` 方法的工作原理與 `.extend()` 相似，但它不會讓你用不可賦值的架構覆寫現有的屬性。換句話說，安全擴充的結果會推論出繼承（[`extends`](https://www.typescriptlang.org/docs/handbook/2/conditional-types.html#conditional-type-constraints) ）自原本的型別（在 TypeScript 上的型別限縮概念）。

```ts
z.object({ a: z.string() }).safeExtend({ a: z.string().min(5) }); // ✅
z.object({ a: z.string() }).safeExtend({ a: z.any() }); // ✅
z.object({ a: z.string() }).safeExtend({ a: z.number() });
//                                       ^  ❌ ZodNumber is not assignable 
```

使用 `.safeExtend()` 方法來擴充包含精煉（`refine()` 方法）的架構。（一般的 `.extend()` 使用在包含精煉的架構裡會拋出錯誤）。

<Tabs groupId="lib" items={["Zod", "Zod Mini"]}>
<Tab value="Zod">
```ts

  a: z.string(),
  b: z.string()
}).refine(user => user.a === user.b);

// Extended inherits the refinements of Base
const Extended = Base.safeExtend({
  a: z.string().min(10)
});
```
</Tab>
<Tab value="Zod Mini">
```ts
const Base = z.object({

  b: z.string()

  a: z.string().min(10)
```

## 遞迴（循環參照）物件

欲定義自我參照式型別，請使用 [getter](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/get) 函式的關鍵字，這讓 JavaScript 在執行期時解析循環架構。

```ts
const Category = z.object({
  name: z.string(),
  get subcategories(){
    return z.array(Category)
  }
});

type Category = z.infer<typeof Category>;
// { name: string; subcategories: Category[] }
```

<Callout type="warn"> 
  雖然支援遞迴架構，但將循環資料傳入 Zod 會導致無限迴圈。
</Callout>

也可以使用*相互遞迴型別（mutually recursive types）*：

```ts
const User = z.object({
  email: z.email(),
  get posts(){
    return z.array(Post)
  }
});

const Post = z.object({
  title: z.string(),
  get author(){
    return User
  }
});
```

所有物件 API（`.pick()`、`.omit()`、`.required()`、`.partial()` 等方法）都會如預期般運作。

### 循環參照錯誤（Circularity errors）

由於 TypeScript 的限制，遞迴型別推論可能很微妙，它只在某些情況下有效。一些較複雜的型別可能會觸發遞迴型別錯誤：

```ts
const Activity = z.object({
  name: z.string(),
  get subactivities() {
    // ^ ❌ 'subactivities' implicitly has return type 'any' because it does not
    // have a return type annotation and is referenced directly or indirectly
    // in one of its return expressions.ts(7023)

    return z.nullable(z.array(Activity));
  },
});
```

在此情境下，可以在出錯的 getter 函式上使用型別註解來解決錯誤：

```ts
const Activity = z.object({
  name: z.string(),
  get subactivities(): z.ZodNullable<z.ZodArray<typeof Activity>> {
    return z.nullable(z.array(Activity));
  },
});
```

{/* Some general rules of thumb for avoiding circularity  */}

## 排他性聯集（XOR）

排他性聯集（XOR）必須只能有一個選項符合的聯集。與任何選項匹配時都會成功的一般聯集不同，`z.xor()` 在零個選項匹配或多個選項匹配時都會失敗。

```ts
const schema = z.xor([z.string(), z.number()]);

schema.parse("hello"); // ✅ passes
schema.parse(42);      // ✅ passes
schema.parse(true);    // ❌ fails (zero matches)
```

這在確保各聯集選項的互斥性時非常有用：

```ts
// Validate that exactly ONE of these matches
const payment = z.xor([
  z.object({ type: z.literal("card"), cardNumber: z.string() }),
  z.object({ type: z.literal("bank"), accountNumber: z.string() }),
]);

payment.parse({ type: "card", cardNumber: "1234" }); // ✅ passes
```

若輸入值可以匹配多個選填的選項，`z.xor()` 將會失敗：

```ts
const overlapping = z.xor([z.string(), z.any()]);
overlapping.parse("hello"); // ❌ fails (matches both string and any)
```


## 鑑別式聯集（discriminated union）

一個[鑑別式聯集（discriminated union）](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions)是一種特殊的聯集形式，其一，所有的聯集選項都是物件架構；其二，共用一個特定的鍵值（鑑別者，"discriminator"）。基於鑑別者的值讓 TypeScript 能夠「限縮」型別簽章。

```ts
type MyResult =
  | { status: "success"; data: string }
  | { status: "failed"; error: string };

function handleResult(result: MyResult){
  if(result.status === "success"){
    result.data; // string
  } else {
    result.error; // string
  }
}
```

當然也可以用一般的 `z.union()` 來表示。但正規聯集比較*簡單粗暴*——它們會依序檢查每個選填的輸入值，然後回傳第一個通過的選項，這對於大型的聯集會影響效能。

因此，Zod 提供了一個 `z.discriminatedUnion()` API，使用 *鑑別鍵*（discriminator key）來使解析更有效率。


```ts
const MyResult = z.discriminatedUnion("status", [
  z.object({ status: z.literal("success"), data: z.string() }),
  z.object({ status: z.literal("failed"), error: z.string() }),
]);
```

每個選項應該是一個*物件架構*，且其鑑別欄位（例如上例中的`status` 欄位）對應自某個實字值，或一組值，通常是：`z.enum()`、`z.literal()`、`z.null()` 或 `z.undefined()`。

{/* 
<Callout>
  In Zod 3, you were required to specify the discriminator key as the first argument. This is no longer necessary, as Zod can now automatically detect the discriminator key.

  ```ts
  const MyResult = z.discriminatedUnion("status", [
    z.object({ status: z.literal("success"), data: z.string() }),
    z.object({ status: z.literal("failed"), error: z.string() }),
  ]);
  ```

  If Zod can't find a discriminator key, it will throw an error at schema creation time.
</Callout> */}

<Accordions type="single">
<Accordion title="Nesting discriminated unions">

  For advanced use cases, discriminated unions can be nested. Zod will figure out the optimal parsing strategy to leverage the discriminators at each level.

  ```ts
  const BaseError = { status: z.literal("failed"), message: z.string() };
  const MyErrors = z.discriminatedUnion("code", [
    z.object({ ...BaseError, code: z.literal(400) }),
    z.object({ ...BaseError, code: z.literal(401) }),
    z.object({ ...BaseError, code: z.literal(500) }),
  ]);

  const MyResult = z.discriminatedUnion("status", [
    z.object({ status: z.literal("success"), data: z.string() }),
    MyErrors
  ]);
  ```

</Accordion>
</Accordions>


## 交集

交集型別（`A & B`）代表邏輯上的 "AND"。

```ts
const a = z.union([z.number(), z.string()]);
const b = z.union([z.number(), z.boolean()]);
const c = z.intersection(a, b);

type c = z.infer<typeof c>; // => number
```

這對於兩個物件型別的交集很實用。

```ts
const Person = z.object({ name: z.string() });
type Person = z.infer<typeof Person>;

const Employee = z.object({ role: z.string() });
type Employee = z.infer<typeof Employee>;

const EmployedPerson = z.intersection(Person, Employee);
type EmployedPerson = z.infer<typeof EmployedPerson>;
// Person & Employee
```

<Callout type="warn">
  當合併物件架構時，請使用 [`A.extend(B)`](#extend)，而非交集。使用`.extend()` 會得到一個新的物件架構，而 `z.intersection(A, B)` 會回傳一個 `ZodIntersection` 實例，這個實例缺乏常用的物件方法，例如 `pick` 和 `omit`。
</Callout>

## Records

Record 架構用於驗證例如：`Record<string,string>` 的型別。

### `z.record` 方法

```ts
const IdCache = z.record(z.string(), z.string());
type IdCache = z.infer<typeof IdCache>; // Record<string, string>

IdCache.parse({
  carlotta: "77d2586b-9e8e-4ecf-8b21-ea7e0530eadd",
  jimmie: "77d2586b-9e8e-4ecf-8b21-ea7e0530eadd",
});
```

「鍵」的架構可以是任何可賦值給 `string | number | symbol` 的 Zod 架構。

```ts
const Keys = z.union([z.string(), z.number(), z.symbol()]);
const AnyObject = z.record(Keys, z.unknown());
// Record<string | number | symbol, unknown>
```

欲建立包含由列舉定義的鍵，其物件架構如下：

```ts
const Keys = z.enum(["id", "name", "email"]);
const Person = z.record(Keys, z.string());
// { id: string; name: string; email: string }
```

### `z.partialRecord` 方法


<Callout>
  **Zod 4** - 在 Zod 4 中，若傳入一個 `z.enum` 作為 `z.record()` 的第一個參數，Zod 將會窮盡（exhaustively）檢查輸入值的鍵值是否存在於列舉值中，此舉與 TypeScript 的行為一致：

  ```ts
  type MyRecord = Record<"a" | "b", string>;
  const myRecord: MyRecord = { a: "foo", b: "bar" }; // ✅
  const myRecord: MyRecord = { a: "foo" }; // ❌ missing required key `b`
  ```

  在 Zod 3 中，並沒有做窮盡檢查，若要重現舊行為，請使用 `z.partialRecord()` 方法。

</Callout>

若想要*局部的* Record 型別，請使用 `z.partialRecord()` 方法。使用此方法會略過 Zod 在鍵值上使用 `z.enum()` 和 `z.literal()` 之架構所執行的窮盡檢查。

```ts
const Keys = z.enum(["id", "name", "email"]).or(z.never()); 
const Person = z.partialRecord(Keys, z.string());
// { id?: string; name?: string; email?: string }
```

### `z.looseRecord` 方法


```ts
const schema = z.object({ name: z.string() }).passthrough()
  .and(z.looseRecord(z.string().regex(/^S_/), z.string()))
  .and(z.looseRecord(z.string().regex(/^N_/), z.number()));

schema.parse({ 
  name: "John",
  other: "value",    // passes through unchanged
  S_foo: "bar",     // validated as string
  N_count: 123,     // validated as number
});
```

<Accordions>
<Accordion title="A note on numeric keys">

雖然 TypeScript 提供定義具數值「鍵」之 Record 型別（例：`Record<number,unknown>`），然而實際上數值鍵並不存在於 JavaScript 中，JavaScript 會將所有數值的鍵轉換為字串。

```ts
const myObject = { 1: "one" };

Object.keys(myObject); 
// => ["1"]
```

如上例所示，JavaScript 引擎會自動將所有數值的鍵轉換成字串，因此，在 `z.record()` 內使用 `z.number()` 做為鍵的架構，在解析時總會拋出錯誤，但為了與 TypeScript 的型別系統保持一致，Zod仍默許這樣做。

</Accordion></Accordions>

## Instanceof

您可以使用 `z.instanceof` 來檢查輸入值是否屬於某類別的實例，這對驗證第三方函式庫的類別之輸入值來說非常有用。

```ts
class Test {
  name: string;
}

const TestSchema = z.instanceof(Test);

TestSchema.parse(new Test()); // ✅
TestSchema.parse("whatever"); // ❌
```

### 類別屬性

根據 Zod 架構來驗證類別之實體的特定屬性：

```ts
const blobSchema = z.instanceof(URL).check(
  z.property("protocol", z.literal("https:" as string, "Only HTTPS allowed"))
);

blobSchema.parse(new URL("https://example.com")); // ✅
blobSchema.parse(new URL("http://example.com")); // ❌
```

`z.property()` API 適用於任何資料型別（但與 `z.instanceof()` 搭配使用時最有成效）。

```ts
const blobSchema = z.string().check(
  z.property("length", z.number().min(10))
);

blobSchema.parse("hello there!"); // ✅
blobSchema.parse("hello."); // ❌
```

#### `when` 方法

> **注意** - 這是進階使用者的功能，請謹慎使用，以免增加精煉內部產生不可預期錯誤的可能性。

預設情況下，若已遇到任何*不可續行性*（non-continuable）的問題，精煉就不會執行。在將值傳入任何精煉函式之前，Zod 會小心確保值的型別簽章是正確的。

```ts
const schema = z.string().refine((val) => {
  return val.length > 8
});

schema.parse(1234); // invalid_type: refinement won't be executed
```

## 編解碼器

> **新功能** - 於 Zod 4.1 版本推出，更多資訊請參閱[編解碼器](/codecs) 頁面。

編解碼器是一種特殊的架構，可在兩個其他架構之間實現*雙向轉換*。

```ts
const stringToDate = z.codec(
  z.iso.datetime(),  // input schema: ISO date string
  z.date(),          // output schema: Date object
  {
    decode: (isoString) => new Date(isoString), // ISO string → Date
    encode: (date) => date.toISOString(),       // Date → ISO string
  }
);
```

一般的 `.parse()` 流程會執行*正向轉換*，它會呼叫變解碼器中的 `decode` 函式。

```ts
stringToDate.parse("2024-01-15T10:30:00.000Z"); // => Date
```

也可以使用頂層的 `z.decode()` 函式。與 `.parse()`（接受 `unknown` 輸入值）不同之處在於，`z.decode()` 期望強型別的輸入值（上例中為 `string`）。

```ts
z.decode(stringToDate, "2024-01-15T10:30:00.000Z"); // => Date
```

若要執行*逆向轉換*，請使用逆向的方法：z.encode()`。

```ts
z.encode(stringToDate, new Date("2024-01-15")); // => "2024-01-15T00:00:00.000Z"
```

如需詳細資訊，請參閱[編解碼器](/codecs)頁面，該頁面包含常用編解碼器的實作，可以直接複製/貼上至專案中：

## 預錯值（Prefaults）

在 Zod 中，設定*預設值*會使解析過程短路。若輸入值是 `undefined`，預設值將主動地回傳。為此，預設值必須符合架構的*輸出型別*。

```ts
const schema = z.string().transform(val => val.length).default(0);
schema.parse(undefined); // => 0
```

有時候定義*預錯值（Prefault）*（預先解析預設值）是很有用的。若輸入值為 `undefined`，則會改用預錯值來進行解析，解析過程中*不會*造成短路。因此，預錯值的型別必須符合*輸入值型別。

```ts
z.string().transform(val => val.length).prefault("tuna");
schema.parse(undefined); // => 4
```

若想要傳入一些輸入值至「包含資料竄改邏輯」的精煉時格外有用。

```ts
const a = z.string().trim().toUpperCase().prefault("  tuna  ");
a.parse(undefined); // => "TUNA"

const b = z.string().trim().toUpperCase().default("  tuna  ");
b.parse(undefined); // => "  tuna  "
```

## 品牌型別（Branded types）

TypeScript 的型別系統是[結構化的（structural）](https://www.typescriptlang.org/docs/handbook/type-compatibility.html)，意即兩個在結構上等同的型別被視為相同。

```ts
type Cat = { name: string };
type Dog = { name: string };

const pluto: Dog = { name: "pluto" };
const simba: Cat = pluto; // works fine
```

在某些情況下，在 TypeScript 內模擬「[名義型別（nominal typing）](https://en.wikipedia.org/wiki/Nominal_type_system)」是可預期的。使用「*品牌型別*（branded type）」來實現，又稱為「不透明型別」（opaque type）。

```ts
const Cat = z.object({ name: z.string() }).brand<"Cat">();
const Dog = z.object({ name: z.string() }).brand<"Dog">();

type Cat = z.infer<typeof Cat>; // { name: string } & z.$brand<"Cat">
type Dog = z.infer<typeof Dog>; // { name: string } & z.$brand<"Dog">

const pluto = Dog.parse({ name: "pluto" });
const simba: Cat = pluto; // ❌ not allowed
```

在實際的底層實作中，這透過附加一個「品牌」至架構的推論型別。

```ts
const Cat = z.object({ name: z.string() }).brand<"Cat">();
type Cat = z.infer<typeof Cat>; // { name: string } & z.$brand<"Cat">
```

有了品牌屬性，任何無印（unbranded）的資料結構就不能再賦值給推論的型別。而必須使用構架解析某些資料，才能得到付品牌的資料。


> 值得注意的是，品牌型別並不影響執行期 `.parse` 的結果。它僅是靜態的結構。

## JSON

驗證任何 JSON 可編碼的值：

```ts
const jsonSchema = z.json();
```

這是一個便利的 API 回傳有以下聯集型別的架構：

```ts
const jsonSchema = z.lazy(() => {
  return z.union([
    z.string(params), 
    z.number(), 
    z.boolean(), 
    z.null(), 
    z.array(jsonSchema), 
    z.record(z.string(), jsonSchema)
  ]);
});
```



## 函式

Zod 提供了一個 `z.function()` 方法來定義 Zod 驗證函式。如此一來，就可避免將驗證代碼與商業邏輯混雜在一起。

```ts
const MyFunction = z.function({
  input: [z.string()], // parameters (must be an array or a ZodTuple)
  output: z.number()  // return type
});

type MyFunction = z.infer<typeof MyFunction>;
// (input: string) => number
```

函式架構有一個 `.implement()` 方法，它接受一個函式，並回傳一個自動驗證其輸入和輸出資料的新函式。

```ts
const computeTrimmedLength = MyFunction.implement((input) => {
  // TypeScript knows input is a string!
  return input.trim().length;
});

computeTrimmedLength("sandwich"); // => 8
computeTrimmedLength(" asdf "); // => 4
```

若輸入值無效，此函式會拋出 `ZodError` 錯誤：

```ts
computeTrimmedLength(42); // throws ZodError
```

若只關心輸入值的驗證，可省略 `output` 欄位。

```ts
const MyFunction = z.function({
  input: [z.string()], // parameters (must be an array or a ZodTuple)
});

const computeTrimmedLength = MyFunction.implement((input) => input.trim.length);
```


使用 `.implementAsync()` 方法來建立一個非同步函式。

```ts
const computeTrimmedLengthAsync = MyFunction.implementAsync(
  async (input) => input.trim().length
);

computeTrimmedLengthAsync("sandwich"); // => Promise<8>
```

## 自定義

您可使用 `z.custom()` 為任何 TypeScript 型別建立 Zod 架構。這對於為 Zod 不支援的型別建立架構非常有用，例如：樣板字串實字。

```ts
const px = z.custom<`${number}px`>((val) => {
  return typeof val === "string" ? /^\d+px$/.test(val) : false;
});

type px = z.infer<typeof px>; // `${number}px`

px.parse("42px"); // "42px"
px.parse("42vw"); // throws;
```

若不提供驗證函式，Zod 將允許任何值。而這可能會很危險！

```ts
z.custom<{ arg: string }>(); // performs no validation
```

您可透過傳入第二個參數，自訂錯誤訊息和其他選填的項目。這個參數的作用與 [`.refine`](#refine) 的 params 參數相同。

```ts
z.custom<...>((val) => ..., "custom error message");
```
