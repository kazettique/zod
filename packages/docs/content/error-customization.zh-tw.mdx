{/* ## `$ZodError` */}

在 Zod 中，驗證錯誤會以 `z.core.$ZodError` 類別的實例形式出現。

> `zod` 套件中的 `ZodError` 類別是實作一些額外便利方法的子類別。

`$ZodError` 的實例包含一個 `.issues` 陣列。每個問題（issue）包含一個可讀性高的錯誤訊息（`message`）以及關於該問題所附加的結構化元資料（metadata）。


<Tabs groupId="lib" items={["Zod", "Zod Mini"]}>
<Tab value="Zod">
```ts
import * as z from "zod";

const result = z.string().safeParse(12); // { success: false, error: ZodError }
result.error.issues;
// [
//   {
//     expected: 'string',
//     code: 'invalid_type',
//     path: [],
//     message: 'Invalid input: expected string, received number'
//   }
// ]
```
</Tab>
<Tab value="Zod Mini">
```ts
import * as z from "zod/mini";

const result = z.string().safeParse(12); // { success: false, error: z.core.$ZodError }
result.error.issues;
// [
//   {
//     expected: 'string',
//     code: 'invalid_type',
//     path: [],
//     message: 'Invalid input'
//   }
// ]
```

</Tab>
</Tabs>

{/* ## Customization */}

每個問題都包含一個 `message` 屬性，內含可由可讀性高的錯誤訊息，錯誤訊息可以多種方式自訂。


## `error` 參數

幾乎每個 Zod API 都接受選填的錯誤訊息。

```ts
z.string("Not a string!");
```

此自訂錯誤在 `message` 屬性裡反映此架構的任何驗證問題。

```ts
z.string("Not a string!").parse(12);
// ❌ throws ZodError {
//   issues: [
//     {
//       expected: 'string',
//       code: 'invalid_type',
//       path: [],
//       message: 'Not a string!'   <-- 👀 custom error message
//     }
//   ]
// }
```

所有 `z` 函式和架構方法都可以自訂錯誤訊息。

<Tabs groupId="lib" items={["Zod", "Zod Mini"]}>
<Tab value="Zod">
```ts
z.string("Bad!");
z.string().min(5, "Too short!");
z.uuid("Bad UUID!");
z.iso.date("Bad date!");
z.array(z.string(), "Not an array!");
z.array(z.string()).min(5, "Too few items!");
z.set(z.string(), "Bad set!");
```
</Tab>
<Tab value="Zod Mini">
```ts
z.string("Bad!");
z.string().check(z.minLength(5, "Too short!"));
z.uuid("Bad UUID!");
z.iso.date("Bad date!");
z.array(z.string(), "Bad array!");
z.array(z.string()).check(z.minLength(5, "Too few items!"));
z.set(z.string(), "Bad set!");
```
</Tab>
</Tabs>

您也可以傳入一個有 `error` 參數的 params 物件。

<Tabs groupId="lib" items={["Zod", "Zod Mini"]}>
<Tab value="Zod">
```ts
z.string({ error: "Bad!" });
z.string().min(5, { error: "Too short!" });
z.uuid({ error: "Bad UUID!" });
z.iso.date({ error: "Bad date!" });
z.array(z.string(), { error: "Bad array!" });
z.array(z.string()).min(5, { error: "Too few items!" });
z.set(z.string(), { error: "Bad set!" });
```
</Tab>
<Tab value="Zod Mini">
```ts
z.string({ error: "Bad!" });
z.string().check(z.minLength(5, { error: "Too short!" }));
z.uuid({ error: "Bad UUID!" });
z.iso.date({ error: "Bad date!" });
z.array(z.string(), { error: "Bad array!" });
z.array(z.string()).check(z.minLength(5, { error: "Too few items!" }));
z.set(z.string(), { error: "Bad set!" });
```

</Tab>
</Tabs>


`error` 參數是選填的函式。錯誤自訂函式在 Zod 術語裡稱為錯誤映射（**error map**）。如果發生驗證錯誤，錯誤映射會在解析時執行。

```ts
z.string({ error: ()=>`[${Date.now()}]: Validation failure.` });
```

<Callout>
**Note** - 在 Zod v3 中，`message`（一個字串）和 `errorMap`（一個函式）有獨立的參數。這些參數在 Zod 4 中統一為 `error`。
</Callout>

錯誤映射會接收一個上下文物件（context object），您可以用它來根據驗證問題自訂錯誤訊息。

```ts
z.string({
  error: (iss) => iss.input === undefined ? "Field is required." : "Invalid input."
});
```

對於進階的情況，`iss` 物件會提供額外的資訊，您可以用來自訂錯誤。

```ts
z.string({
  error: (iss) => {
    iss.code; // the issue code
    iss.input; // the input data
    iss.inst; // the schema/check that originated this issue
    iss.path; // the path of the error
  },
});
```

根據您使用的 API 可能還有其他可用的屬性。使用 TypeScript 的自動完成（autocomplete）功能來探索可用的屬性。

```ts
z.string().min(5, {
  error: (iss) => {
    // ...the same as above
    iss.minimum; // the minimum value
    iss.inclusive; // whether the minimum is inclusive
    return `Password must have ${iss.minimum} characters or more`;
  },
});
```

回傳 `undefined` 來避免自訂錯誤訊息，並使用預設訊息。（具體來說，Zod 會將控制權交給[優先權鏈（precedence chain）](#error-precedence) 中的下一個錯誤映射）。這對於選擇性地自訂某些錯誤訊息下很有用。

```ts
z.int64({
  error: (issue) => {
    // override too_big error message
    if (issue.code === "too_big") {
      return { message: `Value must be <${issue.maximum}` };
    }

    //  defer to default
    return undefined;
  },
});
```

## 每段錯誤自訂

若要為每次解析自訂錯誤訊息，請將錯誤映射傳入解析方法：

```ts
const schema = z.string();

schema.parse(12, {
  error: iss => "per-parse custom error"
});
```

這比任何架構層級的自訂訊息具有*較低的優先權*。

```ts
const schema = z.string({ error: "highest priority" });
const result = schema.safeParse(12, {
  error: (iss) => "lower priority",
});

result.error.issues;
// [{ message: "highest priority", ... }]
```

`iss` 物件是所有可能的問題之[區別聯集型別](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions)，使用 `code` 屬性來區分它們。

> 關於所有 Zod 問題代碼的細節，請參閱 [`zod/v4/core`](/packages/core#issue-types)文件。

```ts
const result = schema.safeParse(12, {
  error: (iss) => {
    if (iss.code === "invalid_type") {
      return `invalid type, expected ${iss.expected}`;
    }
    if (iss.code === "too_small") {
      return `minimum is ${iss.minimum}`;
    }
    // ...
  }
});
```

### 在驗證問題中納入輸入值

預設情況下 Zod 不會在問題中包含輸入值，這是為了防止無意間記錄可能敏感的輸入值。若要在每個問題中包含輸入值，請使用 `reportInput` 屬性：

```ts
z.string().parse(12, {
  reportInput: true
})

// ZodError: [
//   {
//     "expected": "string",
//     "code": "invalid_type",
//     "input": 12, // 👀
//     "path": [],
//     "message": "Invalid input: expected string, received number"
//   }
// ]
```

## 全域的自訂錯誤

若要全域錯誤映射，請使用 `z.config()` 設定 Zod 的 `customError` 配置設定：

```ts
z.config({
  customError: (iss) => {
    return "globally modified error";
  },
});
```

全域錯誤訊息的*優先序*低於架構層級或每次解析的錯誤訊息。

`iss` 物件是所有可能問題型別之[區別聯集型別](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions)。使用 `code` 屬性來區分它們。

> 關於所有 Zod 問題代碼的細目，請參閱 [`zod/v4/core`](/packages/core#issue-types) 文件。

```ts
z.config({
  customError: (iss) => {
    if (iss.code === "invalid_type") {
      return `invalid type, expected ${iss.expected}`;
    }
    if (iss.code === "too_small") {
      return `minimum is ${iss.minimum}`;
    }
    // ...
  },
});
```

## 多語系

為了支援多語系之錯誤訊息，Zod 提供了幾個內建的語系。這些都是從 `zod/v4/core` 套件匯出的。

> **注意** - 標準 `zod` 函式庫會自動載入英語（`en`）語言，Zod Mini 預設不載入任何語系；相反地，所有錯誤訊息預設值為 `Invalid input`。

<Tabs groupId="lib" items={["Zod", "Zod Mini"]}>
<Tab value="Zod">
```ts
import * as z from "zod";
import { en } from "zod/locales"

z.config(en());
```
</Tab>
<Tab value="Zod Mini">
```ts
import * as z from "zod/mini"
import { en } from "zod/locales";

z.config(en());
```
</Tab>
</Tabs>

若要延遲載入（lazy load）一個語系，請考慮使用動態匯入：

```ts
import * as z from "zod";

async function loadLocale(locale: string) {
  const { default: locale } = await import(`zod/v4/locales/${locale}.js`);
  z.config(locale());
};

await loadLocale("fr");
```

為方便起見，所有的語系都從 `zod` 匯出為 `z.locales`。在某些打包工具中，可能無法達成樹搖優化。

<Tabs groupId="lib" items={["Zod", "Zod Mini"]}>
<Tab value="Zod">
```ts
import * as z from "zod";

z.config(z.locales.en());
```
</Tab>
<Tab value="Zod Mini">
```ts
import * as z from "zod/mini"

z.config(z.locales.en());
```
</Tab>
</Tabs>

## 錯誤優先序

以下是決定錯誤優先序的快速參考：若已定義了多個自訂錯誤訊息，何者優先？以下是優先序的說明（*從最高至最低*）：

1. **架構層級錯誤** - 任何寫死（hard coded）到架構定義中的錯誤訊息。

  ```ts
  z.string("Not a string!");
  ```

2. **每次的解析錯誤** - 傳入 `.parse()` 方法中的自訂錯誤訊息。

  ```ts
  z.string().parse(12, {
    error: (iss) => "My custom error"
  });
  ```

3. **全域錯誤對照表** - 傳入 `z.config()` 之自訂錯誤對照表。

  ```ts
  z.config({
    customError: (iss) => "My custom error"
  });
  ```

4.**地方語系之錯誤對照表** - 傳入 `z.config()` 之自訂錯誤對照表。

  ```ts
  z.config(z.locales.en());
