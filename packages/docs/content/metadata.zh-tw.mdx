為了文件化、程式碼生成、AI 結構輸出、表單驗證以及其他目的，將架構與一些額外的*元資料*相關聯通常是有很有幫助的。

## 註冊

Zod 的元資料（metadata）是透過*註冊*來處理的。註冊是架構的集合，每個架構都與一些*強型別*的元資料相關聯。欲建立一個簡單的註冊表：

```ts
import * as z from "zod";

const myRegistry = z.registry<{ description: string }>();
```

在此註冊表中註冊、查詢及移除架構：

```ts
const mySchema = z.string();

myRegistry.add(mySchema, { description: "A cool schema!"});
myRegistry.has(mySchema); // => true
myRegistry.get(mySchema); // => { description: "A cool schema!" }
myRegistry.remove(mySchema);
myRegistry.clear(); // wipe registry
```

TypeScript 強制每個架構的元資料符合註冊表的**元資料型別**。

```ts
myRegistry.add(mySchema, { description: "A cool schema!" }); // ✅
myRegistry.add(mySchema, { description: 123 }); // ❌
```

> **`id` 的特殊處理方式** - Zod 註冊表會特別處理 `id` 屬性。若有多個架構以相同的 `id` 值註冊，則會產生 `Error`。這對所有註冊表都適用，包括全域註冊表。


### `.register()`

> **注意** - 這個方法很特別，它不會回傳一個新的架構；相反地，它會回傳原始的架構。沒有其他 Zod 方法如此！包括 `.meta()` 和 `.describe()`（文件如下），它們會回傳一個新的實例。

架構提供 `.register()` 方法以便更方便地將其加入註冊表。

```ts
const mySchema = z.string();

mySchema.register(myRegistry, { description: "A cool schema!" });
// => mySchema
```

在「內嵌」的架構中定義元資料。

```ts
const mySchema = z.object({
  name: z.string().register(myRegistry, { description: "The user's name" }),
  age: z.number().register(myRegistry, { description: "The user's age" }),
})
```

<Callout>
若註冊表的定義沒有元資料型別，您可以將它當成一般的「集合」來使用，不需要元資料。

```ts
const myRegistry = z.registry();

myRegistry.add(z.string());
myRegistry.add(z.number());
```
</Callout>


## 元資料（Metadata）

### `z.globalRegistry`

為了方便起見，Zod 提供了一個全域註冊表（`z.globalRegistry`），可用來儲存元資料，以便產生 JSON Schema 或其他用途。它接受下列元資料：

```ts
export interface GlobalMeta {
  id?: string ;
  title?: string ;
  description?: string;
  deprecated?: boolean;
  [k: string]: unknown;
}
```

在 `z.globalRegistry` 中為架構註冊一些元資料：

```ts
import * as z from "zod";

const emailSchema = z.email().register(z.globalRegistry, { 
  id: "email_address",
  title: "Email address",
  description: "Your email address",
  examples: ["first.last@example.com"]
});
```

欲全域擴充 `GlobalMeta` 介面，請使用[*宣告式合併（declaration merging）*](https://www.typescriptlang.org/docs/handbook/declaration-merging.html)。在您程式碼庫的任何地方加入下列內容。慣例會在專案根目錄建立一個 `zod.d.ts` 檔案。

```ts
declare module "zod" {
  interface GlobalMeta {
    // add new fields here
    examples?: unknown[];
  }
}

// forces TypeScript to consider the file a module
export {}
```

### `.meta()`

若要使用更方便的方法，請使用 `.meta()` 方法在 `z.globalRegistry` 中註冊架構。

呼叫 `.meta()` 且不帶參數可*擷取（retrieve）*架構的元資料。


```ts
emailSchema.meta();
// => { id: "email_address", title: "Email address", ... }
```

元資料與*特定的架構實例相關聯*，這一點必須牢記，尤其是 Zod 方法是不可變的——它們永遠回傳一個新的實例。

```ts
const A = z.string().meta({ description: "A cool string" });
A.meta(); // => { description: "A cool string" }

const B = A.refine(_ => true);
B.meta(); // => undefined
```

### `.describe()`

<Callout>
為了與 Zod 3 相容，`.describe()` 方法仍然存在，但仍推薦使用`.meta()` 方法。
</Callout>

`.description()` 方法是在 `z.globalRegistry` 中僅用 `description` 欄位註冊架構的簡寫法。

## 自訂註冊

您已經看過自訂註冊表的簡單範例：


```ts
import * as z from "zod";

const myRegistry = z.registry<{ description: string };>();
```

讓我們來看看一些更進階的範例。

### 推論型別的參照

元資料型別參照架構的*型別推論*通常是值得參考的。例如：您可能需要一個 `examples` 欄位來包含架構輸出的範例。

```ts
import * as z from "zod";

type MyMeta = { examples: z.$output[] };
const myRegistry = z.registry<MyMeta>();

myRegistry.add(z.string(), { examples: ["hello", "world"] });
myRegistry.add(z.number(), { examples: [1, 2, 3] });
```

特殊符號 `z.$output` 是對架構推論的輸出型別（`z.infer<typeof schema>`）的參照。同樣您也可以使用 `z.$input` 來參照輸入型別。

### 約束架構型別

傳送第二個泛型別到 `z.registry()` 以限制可加入註冊表的架構型別。在此範例中，註冊表只接受字串架構。

```ts
import * as z from "zod";

const myRegistry = z.registry<{ description: string }, z.ZodString>();

myRegistry.add(z.string(), { description: "A number" }); // ✅
myRegistry.add(z.number(), { description: "A number" }); // ❌ 
//             ^ 'ZodNumber' is not assignable to parameter of type 'ZodString' 
```
